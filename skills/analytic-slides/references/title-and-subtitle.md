# Titles and subtitles

Title style follows purpose. The builder prints the expected style in its QA report; it never rewrites titles.

| Purpose | Title style | Example |
|---|---|---|
| inform / persuade (results) | finding / claim | "Channel activity fell sharply during Beryl" |
| explain (methods) | descriptive | "Defining three spatial supports for AIS" |
| validate | decision-oriented question or action | "Three spatial definitions require validation" |
| compare | contrast | "Regional activity masks channel disruption" |
| introduce | question / framing | "How should we measure port disruption?" |
| decide / recommend | action | "Validate channel geometry before scaling" |

- One line. About 60 characters is a default, not a law (the builder fails only if the title cannot fit on one line).
- The subtitle narrows the title; it never repeats it. Default for geographic work: `Location · Event/date · scope qualifier`. Omit parts that add nothing, or omit the subtitle entirely.
- Never invent a number for a claim title. A placeholder finding must be marked ILLUSTRATIVE.
